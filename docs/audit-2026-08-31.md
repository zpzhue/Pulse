### P0-1 [x] 进度流管道接错：进度/速度/ETA 永远收不到（实测证实）——✅ 已修复（2026-08-31）

> 修复：`stdout(Stdio::piped())`，`run_download` 改读 stdout；进度模板加 `PULSE|` 字面标记（`download:PULSE|...`）防误匹配；stderr 由辅助线程收尾 4KB，失败时把 yt-dlp 原始报错带进 `error` 事件。探针复测：13 行标记进度全部落在 stdout。

- **位置**：`src-tauri/src/ytdlp.rs`
  - `start_download`（ytdlp.rs:317-322）：`.stdout(Stdio::null())`、`.stderr(Stdio::piped())`
  - `run_download`（ytdlp.rs:365-388）：只从 **stderr** 读 `download:` 模板行
  - 进度模板定义在 ytdlp.rs:202-206
- **根因**：`--progress-template` 的输出走 **stdout**，stderr 只有警告/错误。stdout 被丢弃 → `parse_progress` 永远不触发。
- **实测证据**：用本机 yt-dlp 2026.08.19 + 本地回环 HTTP 下载，模板行（`0.0%|1024|3000000|...`）全部出现在 stdout，stderr 为空；下载成功、进度行 0 条进 stderr。
- **影响**：真实下载时任务永远 0%、无速度/ETA，进程退出后直接跳「已完成」。Dashboard 的「下载速度」恒为 —、「磁盘占用」恒 0（按 `downloadedBytes` 累计）。
- **修复方向**：`stdout(Stdio::piped())`，`run_download` 改从 stdout 读进度行；stderr 另起读取（或先缓冲）用于把 yt-dlp 报错文本带进 `error` 事件（目前失败只有退出码，没有 stderr 原因）。
- **验证**：真实下载一个视频，Dashboard 进度条连续增长、速度/ETA 有值；完成/失败时 `error` 事件含 yt-dlp 的报错文本。

### P1-5 [x] 取消的边角竞态 + 进程组不完整 —— ✅ 已修复（2026-08-31 第二批）

> 修复：`cancel_download` 先 `try_wait()`，已退出则报「已结束，无需取消」不置位；spawn 改 `process_group(0)`，取消用 `killpg(SIGKILL)` 杀整组（含 ffmpeg），失败回退 `kill()`。
> 审查跟进（第四批）改用审计中的原子方案：Unix 上取消判定 = `ExitStatus.signal() == SIGKILL`（进程组被我们击杀的唯一可靠标志），`cancel_requested` 标志在 Unix 分支删除——自然退出（含 zombie 晚收）永不被误标为已取消。单测 `signals_sigkill_death_as_cancelled` 锁定该不变量。

- **位置**：`src-tauri/src/ytdlp.rs` `run_download`（ytdlp.rs:390-399）与 `cancel_download`（ytdlp.rs:415-431）
- **现象**：
  a) 任务已退出但未及从管理表移除的窗口内点取消：`kill()` 对已退出进程返回 `InvalidInput` 被当成功、`cancel_requested` 置位 → 已成功的任务被记为「已取消」（窗口极小，概率低）；
  b) 取消只 SIGKILL 直接子进程，yt-dlp 派生的 ffmpeg（合并/分片阶段）可能成孤儿继续跑。
- **修复方向**：a) `cancel_download` 前先确认任务仍在表且子进程未退出（或以 remove-then-check 原子化）；b) 用 POSIX 进程组（`setsid` + `killpg`）或先杀 ffmpeg 子进程再杀 yt-dlp。
- **验证**：下载中点取消：文件停止增长、无残留 ffmpeg 进程；下载完成瞬间点取消不误标。
